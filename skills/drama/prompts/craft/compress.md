# 缩写 Compress

> 专业技能 · 适时加载 · 使用后向编剧汇报

## 什么时候用

- 功能性场景（铺垫/过渡/信息传递）——必须用最短篇幅完成
- 过程展示（赶路/买菜/做饭/传话）——只给结果不给过程
- 连续 2 个以上场景的情绪密度不足——合并或删掉一个
- 原文有冗长的环境描写或配角闲聊

## 缩写公式

缩写 = **砍过程** + **合并场景** + **用结果替代展示** + **一句台词解决三句台词的事**

## 五种缩写技巧

| 技巧 | 怎么做 | 示例 |
|------|--------|------|
| 跳过过程 | 不写"他走到门口→推开门→走出去"，直接写结果 | `△半个时辰后，他浑身是泥地回来，手里攥着一封信` |
| 合并场景 | 把多个功能相近的场景合并成一个 | 厨房做饭+饭桌闲聊 = 一个场景，"她边盛饭边问" |
| 结果替代 | 不展示"如何得到X"，只展示"得到X后的反应" | `△桌上摆着三张地契。她没问怎么弄到的。` |
| 一句话概括 | 把需要3句对话才能传递的信息压成1句 | "张老板回话了——不行。"（省略了谁去问、怎么问、等了多久） |
| 行为替代解释 | 角色的决定不用台词宣布，用一个动作 | 不是"我决定去长安"，而是`△她把长安的地图折好，放进袖中` |

## 压缩检测（写完场景后问自己）

1. 这个场景能删掉吗？（删掉后剧情不变 = 删）
2. 能合并到上一个场景吗？（同一组人、同一个地点、功能相似 = 合并）
3. 能用 2 行写清楚吗？（现在 5 行 → 尝试压缩到 2 行）
4. 有废话台词吗？（"我办事你放心""知道了" → 删）

## 铁律

1. 功能性场景 ≤ 5 行
2. 不能因压缩而跳过重要的情绪反应——压缩的是**过程**，不是**情感**
3. 压缩后依然要保持完整：前因 → （压缩掉过程）→ 结果+反应

## 典型错误

| ❌ 错 | ✅ 对 |
|------|------|
| 压缩掉情感反应（"她哭了一夜。第二天..."） | 压缩掉哭泣的过程，但保留第二天肿眼泡的特写 |
| 压缩成"他们去查了，查到了" | `△档案室。她在第三排架子的最底层，找到了被烧焦半页的调令`——有画面，有地点 |
| 所有场景都压缩（变成梗概） | 功能性场景压缩，回报性场景展开 |
