# 四案例调研与根因分析（集纲 → 剧本）

> 版本：v1.0  
> 日期：2026-08-07  
> 依据：《测试案例：》PDF（30 页，4 个案例）+ 本机素材（王妈小说/大纲/剧本、其余小说源文件）+ 方寸源码逐文件核对

## 1. 案例速览

### 案例 1：《和高冷老公通感了，哈哈这事闹的》

| 维度 | 内容 |
|---|---|
| 需求 | 50-60 集；一卡（付费点）；一卡前每集 600-700 字，一卡后 400-500 字 |
| 流程实际走向 | **跳过改编指引**（AI 自动补全）→ 大纲 → 集纲（"直接走 AI 默认，无修改"）→ 剧本（只出前 2 集） |
| 编剧操作 | 一集一集出；每集先给改编要点再生成；手动修改后要求"保留修改痕迹并存档"；在文档批注后要求按批注修改 |
| 用户自己总结 | "整体思路为一集一集出，每集会给出原文让 bot 参考，再给出修改方案，最后在文档批注之后按批注再修改，并未走批量生成，**大概率未参考集纲**" |
| 暴露问题 | ① 剧本太长（要求 700-800 字）；② 快切做不出编剧要的信息交代；③ 需要手动贴原文给 bot（说明上下文没自动带原著）；④ 集纲形同虚设 |

### 案例 2：《比格大王萌萌萌萌萌翻全世界！》

| 维度 | 内容 |
|---|---|
| 需求 | 30 集；第 1-54 章；单集 1.5-2.5 分钟；9:16 竖屏；沙雕甜宠/团宠爽文；付费强钩子 EP3/EP7/EP20/EP30；每集结尾 hook；8 条事项确认 |
| 流程实际走向 | 改编指引 → 大纲 → 集纲 → 剧本；**中间反复跳回**（改完大纲又跳回改编指引改 1-61 章/50 集；直出剧本不满意又返回改集纲） |
| 编剧操作 | ① 对改编指引 V3 手动修改，AI 能读出飞书与本地差异；② 要求大纲"每集内容 + 完整叙事大纲"两部分；③ 集纲改为**五集一批次精修**；④ 手改前 3 集集纲格式，要求后续按此格式；⑤ 剧本阶段一集一集出，逐集贴原著、提修改要点 |
| 用户自己总结 | "剧本批量阶段改为了单集出+人为修改；如果人为修改与集纲的故事骨架不冲突则没问题，但**可能会存在人为修改与集纲不对应的情况**" |
| 暴露问题 | ① 用户问"为何要给出原小说？"——剧本上下文没有自动带原著摘录；② 集纲平铺直叙、钩子没意思（用户两次要求强冲突强节奏）；③ 集纲要求加场号 1.2.3；④ 用户给原著让台词参考，但要求场景动作不要照抄 |

### 案例 3：《宿舍求生：从刷广告开始变强》

| 维度 | 内容 |
|---|---|
| 需求 | 60 分钟总时长；一卡前 1-2 分钟/集、一卡后 50 秒-1 分钟；50-60 集；第一季分段漫剧；一卡 EP10；黄金 3 秒；每 3-5 秒一个冲突/信息点；**严格贴合原著、严禁原创**；删减血腥与低俗 |

| 用户自己总结 | "从集纲到剧本采用一段集纲生成一段剧本，再根据剧本反推修改后面的集纲，再生成后续剧本；**但集纲到剧本分段不是预先设置好的规定使用模式，集纲是否被合理地在本地更新、剧本有没有按照新的集纲搭配方寸 skill 走，目前没有准确定论**" |
| 暴露问题 | ① **AI 大量私自原创剧情**（用户两次全作废重写）；② 场景氛围描写弱（要求润色成可视化镜头语言）；③ 用户手写集纲格式（EP9/EP10/…简表）与方寸格式不一致；④ 格式要求完全是用户自定义（横屏场次表头、△、OS、角色名括号） |

| 维度 | 内容 |
|---|---|
| 需求 | 30 集；轻喜豪门反套路偷听心声；每集 1.5-2 分钟；横屏 3D 漫；付费点 EP7-EP9；**学习参考剧本《满级婴语制霸豪门》的风格** |
| 流程实际走向 | 改编指引（多轮确认）→ 大纲（用户直接上传定稿文件）→ 集纲（用户给格式样例 + 手改前 2 集）→ 剧本（**两集一批次精修**） |
| 编剧操作 | ① 上传参考剧本并要求"写入底层逻辑"；② 手写集纲第 1/2 集给 AI 参考格式；③ 上传带批注的 word 文档，要求 AI 读批注改剧本且**禁止改未批注位置**；④ 先用初版集纲做 12 集，再改 13-15 集集纲 |
| 用户自己总结 | "集纲到剧本阶段存在频繁集纲修改且修改的均为部分集数；集纲与剧本的对应关系比较混乱，基本上通过人工上传" |

## 2. 六个跨案例高频行为（编剧的真实工作方式）

1. **一集一集出剧本**（案例 1、2、3 后半段），每集多轮修改；
2. **在飞书/Word 文档手动修改 + 批注**，让 AI 按批注改（案例 1、2、3、4 全部）；
3. **人工上传自己的集纲/剧本作为基准**（案例 3 上传集纲和前 8 集剧本、案例 4 上传定稿大纲和批注 word）；
4. **集纲分段生成、部分修改**（案例 2 五集一批、案例 3 一段集纲一段剧本、案例 4 先做 12 集再改 13-15 集）；
5. **反复跳阶段**（案例 1 跳过改编指引、案例 2 改完大纲跳回改编指引、案例 3 剧本反推改集纲、案例 4 改集纲后回到剧本）；
6. **提供参考剧本/原著片段，要求 AI 学习风格、沿用原著台词**（案例 2 贴原著、案例 3 强制原著台词、案例 4 上传参考剧本）。

## 3. 根因分析

### 根因一：方寸把"AI 生成物"当唯一事实源，而真实工作流是"飞书文档 = 人工修订后的真相"

**证据**：案例 1 "我对其进行了手动修改，请保留我手动修改的痕迹并对该第一集进行存档"；案例 2/3/4 "我对 XX 做了调整你能看到吗"；案例 4 "上传带批注的 word 文档，根据批注修改，禁止修改没有批注的位置"。

**机制缺失**：
- 无批注读取能力（Word/飞书 docx 批注）；
- 无"人工修订 diff → 回灌本地连续性状态"的代码机制；
- 无"当前基准版本"概念（哪一版是编剧确认过的真相）；
- SKILL 文档里的 "Fresh Feishu document / comment workflow" 只是提示词约定，没有实现。

**后果**：bot 续写时读的是本地旧版；人工修改丢失或只被"重读一遍"；集纲与剧本的对应关系越来越乱。

---

### 根因二：集纲没有"批次/单集契约"概念，且格式不统一，剧本阶段拿不到可执行的集纲

**证据**：
- 案例 2 用户要求逐集集纲加"每集主要叙事 + 分场（两到三句话）"，要求加场号 1.2.3；
- 案例 4 用户给出完全不同的集纲格式（`14-1`/`14-2` 叙事式），并要求"只参考格式"；
- 案例 3 用户手写 9-13 集简表（`EP9；核心剧情：…；结尾钩子：…`），AI 据此写剧本。

**代码级影响**：`extract_episode_from_skeleton()` 按方寸固定格式（`## 第N集分集信息` + 特定小节）正则切段；用户格式的集纲**解析必然失败** → 剧本上下文里没有本集契约 → 剧本自由发挥 → "不按集纲写"。

**另一个直接证据**：案例 2 用户问"为何要给出原小说？"——剧本生成的上下文里**没有自动带原著章节摘录**，编剧必须手动贴原文。

---

### 根因三：没有"风格参考/原著贴合度"机制 → 台词生硬、私自原创

**证据**：
- 案例 4："你没学习参考我给出的剧本文件的格式……台词寡淡无味，既没学到剧本语言的轻巧灵动，也没把小说好玩的台词用上，我强制你把小说好的台词用进去，不要自己编机械感很重的词……请你把以上要求写入底层逻辑"；
- 案例 3："台词尽量沿用原著原文台词，少篡改、少自创对白……你之前生成的集纲大量私自原创剧情，完全没有贴合原著内容，多处无依据魔改新增情节，请全部作废"；
- 案例 2："某些对话可以参考原小说即可，但场景、动作画面不要照抄原著的词"。

**方寸现状**：
- 无 few-shot/风格锚点机制（编剧改好的集、参考剧本没有被用作样例）；
- 创作 prompt 是"情绪优先 + 方法论"，天然鼓励再创作，而非贴原著；
- 无"贴合原著程度"可配置项（严格贴合 / 中等 / 自由改编）；
- 编剧的口味（信息度、情绪、轻巧灵动、机械感）无法被量化传递，只能靠一轮轮改。

**后果**：每集 3-4 轮修改不收敛 → 编剧手动改 → 人工成为真正的作者。

---

### 根因四：门控/状态/版本按"整本一次性流水"假设设计，与"分段推进、局部修订"的实际节奏冲突

**证据**：
- 案例 2：先出全集集纲，再五集一批精修；改完集纲又跳回改编指引；
- 案例 3：一段集纲 → 一段剧本 → 剧本反推改集纲 → 再续；
- 案例 4：先用初版集纲做 12 集，再改 13-15 集集纲；
- 案例 1：直接跳过改编指引（用户觉得没必要）。

**方寸现状**：
- `state.json` 只有全局阶段与"当前剧本批次"，无"部分集纲修订版本"概念；
- 门控是全局串行（上一阶段确认才解锁下一阶段），不支持"局部回退"；
- 无"导入外部集纲/剧本作为当前基准"通道；
- 人工确认依赖特定话术 + CLI，用户不按话术就卡死。

**后果**：编剧觉得流程挡路 → 绕开方寸直接用对话操作 → 状态和版本彻底失控 → 周期拉长。

---

### 根因五：审核/重写针对格式与机械问题，无法解决"风格、台词信息度、氛围"这类主观质量

**证据**：
- 案例 3："现在的场景氛围描写很弱……环境渲染、镜头画面、人物肢体动作再写细致，强化悬疑感"；"所有文字统一改成影视可视化镜头语言，全部落地可实拍、可 AI 生成，拒绝虚写"；
- 案例 4："有些台词没有体现信息，也没有展现情绪，就请你把它删掉，或者几句合为一句……要把戏坐在反套路、有喜感的情节点上"。

**方寸现状**：
- `script_review.md` 阻塞条件 10 条多为格式/机械项（场景编号、△、字数、工具占位），语义、台词信息度、氛围靠同一模型自评；
- 重写模式是"定向修严重问题、保留原 beats"，编剧要"换方向/换风格"时无入口；
- 审核不读编剧批注、不比对集纲和原著，无法判断"是否符合编剧口味"。

**后果**：低质量集反复修不收敛；AI 审核"通过了"，编剧却不满意。

---

### 根因六：周期长的结构原因——关键路径全是人工异步往返

- 一集一集出 × 每集 3-4 轮 = 线性增长；
- 每轮 = "AI 改 → 同步文档 → 编剧看 → 批注 → 再改"的完整往返，小时级起步；
- 方寸的 `.pending` 批次锁按 5 集设计，但编剧实际一集一集出 → 锁反而碍事；
- 期望 1 天 vs 实际 4-8 天：不是 AI 慢，是**人工往返次数 × 串行依赖**决定的。

## 4. 对"agent 太灵活、跳出 skill"的判断

编剧跳出方寸用对话直接操作，**不全是 agent 灵活性的问题，更主要的是方寸没有提供编剧需要的操作**：

| 编剧想做的事 | 方寸是否支持 |
|---|---|
| 上传自己的集纲/前几集让 AI 续写 | ❌ 无导入通道 |
| 在文档批注，AI 按批注改 | ❌ 无批注读取 |
| 一集一集出，上下文自动带本集集纲+原著+前集 | ❌ 只能手动贴 |
| 参考一部剧本的风格写 | ❌ 无风格锚点 |
| 部分集数改集纲，后续剧本跟着新集纲走 | ❌ 无版本对应管理 |
| 严格贴原著 / 自由改编 | ❌ 无参数 |

所以"把灵活性输入归纳到各个阶段"的思路是对的：**不是禁止灵活性，而是给灵活性提供正规、快速、可控的通道**，让编剧不需要绕路。

## 5. 改版的五个关键设计（草案，供讨论）

1. **飞书文档 + 批注 = 正式协作层**
   读批注 → diff 人工修订 → 回灌本地连续性状态 → 存档版本 → 后续生成严格基于"编剧确认版"。

2. **批次集纲契约**
   全局集纲（总览）+ 批次集纲（默认 5 集，可配 2/5/10）。批次集纲每集包含：主要叙事（2-3 句）、分场清单（场号/地点/时间/内外）、本集情绪曲线、集末钩子、下集开场状态。剧本严格绑定本批集纲 + 前批确认状态。集纲格式标准化，但支持项目级模板配置（因为编剧会自定义格式）。

3. **风格锚点 + 原著贴合度参数**
   编剧可上传参考剧本 / 自己改好的集作为 few-shot 样例；项目参数"严格贴合原著 / 中等 / 自由改编"；台词可配置"优先沿用原著台词"。

4. **单集/批次生成模式**
   一集一集出时，上下文自动装配：本集集纲 + 前集终稿 + 原著章节摘录 + 风格锚点 + 项目 rules + 编剧批注记录。

5. **审核与重写升级**
   审核增加"对照集纲/原著/编剧批注"检查；支持"按新方向重写"与"按风格参考重写"两种模式；人工批注直接进入审核输入。

## 6. 需要和你对齐的问题

1. 集纲格式：是固定一种标准格式（方寸强制），还是做成可配置模板（默认给标准版，编剧可换）？
2. 风格锚点：由编剧上传参考剧本即可，还是要自动从"已确认集数"中提取风格？
3. 原著贴合度：做成项目级参数（严格/中等/自由），还是每集可调？
4. 批次粒度：2/5/10 可配？批次集纲和剧本必须同批绑定，还是允许错开（如先精修 5 集集纲再出 5 集剧本）？
5. 人工批注的读取：飞书 docx 批注 vs 上传 Word 批注，哪个是主场景？需要支持"批注 → 修改 → 回灌"全自动，还是"批注 → AI 给修改方案 → 编剧确认"？
